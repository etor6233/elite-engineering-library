# Instrucción universal para iniciar un proyecto

Copiar como primera instrucción al agente dentro de un proyecto que tenga acceso a esta biblioteca:

```text
Construye y lleva este proyecto hasta un resultado ejecutable y verificable usando la Elite Engineering Library como sistema de autoridad y aceleración.

Antes de cada ronda usa `render_project_advisory.py` para crear `PROJECT_ADVISORY_<RONDA>.md`, explícamelo en lenguaje simple y registra mi respuesta/evidencia real y su `advisory_prompt_ref`; no tomes el ejemplo como respuesta ni pidas secretos. Pídeme y valida negocio, journeys, datos, documentos/corpus, integraciones, cuentas/sandboxes, UX, seguridad, operación, plataforma y accesos. Para documentos exige inventario único `{class_id,variant_id}`; si una clase almacenará automáticamente, exige modo, mapping consumer exacto, expresión+SHA, output keys, schemas+SHA, capabilities, corpus/evaluación/aprobación y owner exactos. Para `OUTBOX_CDC_CONSUMER`, después del PASS usa `render_consumer_profile.py`: sólo copia diez campos revisados y nunca completa endpoints/secrets/owners/approvals/proofs ni autoriza deploy. Si el proyecto procesa facturas, proformas, packing lists, órdenes, conocimientos de embarque u otros archivos, aplica OFFICIAL_DOCUMENT_INTELLIGENCE_PROFILE.md y crea PROJECT_DOCUMENT_INTELLIGENCE_DECISION.md. Si la entrada seleccionada es portal/API sobre AWS, `AWS_SECURE_DOCUMENT_INTAKE_PACK_PLAN.md` compone 3/35 para presigned PUT a cuarentena más gate local y permanece bloqueado hasta cuenta/IAM/bucket/KMS/policy/CORS/store/eventos/malware; no cubre email/SFTP/scanner/mobile. Para email, el source oficial AWS SES Mail Manager 79314a9 sólo puede adquirirse como referencia rechazada: cero tests/lock, pin CDK vulnerable, CLI inexistente y brechas de tenant/idempotencia/KMS/retención; no desplegarlo ni usarlo para storage automático. Para SFTP hay dos referencias AWS exactas pero rechazadas: secure Transfer Family 474ca07 comparte root/role, deja GuardDuty externo y no maneja delivery duplicado ni copy failure con retry/DLQ; file-transfer-sync 5ee79ee instala dependencias durante synth, compara sólo timestamps, descarta IDs/status terminales y puede escribir el flag de primera copia tras un fallo. No desplegar ninguna ni liberar clean/storage. Para cámara/mobile, AWS receipt 6eb72bf es sólo referencia rechazada: compila, pero carece de tests, tiene SCA 14/13, debug pre-auth, upload sin checksum/version binding y worker que absorbe fallos; no copiar ni persistir automáticamente. Materializa primero `DOCUMENT_PIPELINE_ROUTING_PACK_PLAN.md`: su template habilita cero rutas y su validator exige las 21 clases base y admite toda clase adicional sólo con owners, schemas/fields, corpus, acceso, seguridad y evaluación completos antes de emitir los perfiles seleccionados. Adquiere sólo las fuentes oficiales exactas seleccionadas, prueba sus servicios/código con documentos reales y no habilites almacenamiento automático de un campo sin la evidencia exigida por ese perfil. `DURABLE_DOCUMENT_PIPELINE_PACK_PLAN.md` materializa por separado el plano de control vendor-neutral 5/51 para probar seguridad→original→extracción→evaluación→review→persistencia→evidencia sin seleccionar provider; no lo superpongas en el mismo destino con un perfil provider, porque éstos ya incorporan el mismo orquestador. El sample `prebuilt-documentSearch` preserva contenido/layout y no inventa un schema de negocio; el copy sample no se autoejecuta porque muta recursos externos. Arrancan bloqueados y no configuran infraestructura. Si el blueprint exige detección criptográfica de manipulación del historial, componer aparte `TESSERA_POSIX_EVIDENCE_LOG_PACK_PLAN.md` 2/34: sólo Linux/POSIX y receipts sin datos, con claves existentes, checkpoints externos o witness, backup/restore y operación probados; no reemplaza storage WORM. AWS `amazon-sqs-best-practices-cdk` 54143c7 queda igualmente fijado y rechazado: pese a DLQ/alarma y synth de 17 recursos, no tiene tests/lock, fija CDK vulnerable y Python 3.8, ignora fallos parciales de envío, procesa sólo `Records[0]`, duplica writes por retry y no configura `ReportBatchItemFailures`, conditional effect, replay ni reconciliación.

Para idempotency/partial batch en Python, materialice `AWS_POWERTOOLS_IDEMPOTENT_SQS_BATCH_PACK_PLAN.md`: entrega el handler y los templates separados publicados por AWS Powertools 3.34.0, con bytes/hash y contratos offline. Use sólo wheel/source exacto con receipt y tests del target. No lo trate como worker completo ni asuma Pydantic incluido; aún se exigen event key/version, efecto empresarial, owner fencing cuando haya reclaim, S3 ordering, DLQ/replay/reconciliation, IAM/IaC y E2E AWS. La composición de ambos templates se etiqueta `AUTHORED`, nunca código AWS.

Si además necesita checkpoint/retry/replay durable, materialice `AWS_DURABLE_OBJECT_EVENT_WORKER_PACK_PLAN.md` 3/43. Incluye sólo archivos oficiales AWS separados: Powertools SQS y Durable Execution Python 1.7.0; no inventa ni atribuye a AWS un worker fusionado. Use el core wheel hash-locked y source exacto para reproducir tests; rechace el testing wheel 1.2.1 para ese tag porque su árbol está desalineado. Para pagos, storage, email, mensajería, ads o marketplaces, no materialices un provider por disponibilidad del pack. Selecciona la arquitectura y el stack que mejor satisfagan el blueprint. La base es stack-neutral: no uses TypeScript como backend por defecto ni impongas ningún framework por costumbre. Implementa por vertical slices completos: interfaz, API, identidad/autorización, dominio, datos, eventos, observabilidad, tests, build, deploy y rollback según apliquen. Continúa autónomamente mientras exista trabajo seguro y dentro de alcance. Al cerrar, entrega archivos, decisiones, packs usados, licencias/notices, evidencia, lecciones, riesgos residuales y el siguiente comando reproducible.
```
