Fecha de corte: 2026-08-28.

## 1. Regla de este expediente

Este documento no concede el estado `REUSABLE_PACK`. Registra código público oficial que puede ser descargado o instalado desde una revisión inmutable y separa producto real, SDK de integración, muestra educativa y fuente rechazada.

Ningún artefacto de este expediente autoriza al agente a:

- atribuir a una empresa código escrito por el agente;
- tratar un sample como arquitectura productiva;
- omitir licencia, notices, términos del servicio o credenciales;
- afirmar que una capacidad específica de REVESTEX existe si el upstream sólo aporta primitives;
- copiar desde `main` cuando existe una release estable;
- completar un hueco de negocio con código nuevo y etiquetarlo como `VERBATIM` o `ELITE`.

Estados usados aquí:

| Estado | Uso |
|---|---|
| `PINNED_CANDIDATE` | revisión y licencia fijadas; falta ejecutar el expediente G3–G8 completo |
| `INTEGRATION_ONLY` | SDK/contrato oficial utilizable sólo contra el servicio del proveedor |
| `CONDITIONAL_PLATFORM` | producto real reutilizable, pero exige runtime, licencia o stack del proveedor |
| `SAMPLE_ONLY` | código oficial demostrativo; puede donar fixtures/probes, no gobernar producción |
| `REJECTED` | no se incorpora por licencia, abandono, ausencia de permiso o falta de adecuación |
| `NO_OFFICIAL_CODE_FOUND` | no se localizó código oficial admisible; queda bloqueado, no se inventa |

## 11. Decisión que el agente debe obtener antes de implementar

Antes de materializar dominio REVESTEX, el agente debe pedir una decisión explícita entre:

1. `BUSINESS_CENTRAL_PLATFORM`: reutilizar la fuente empresarial real de Microsoft y exigir acceso/licencia/runtime Business Central; extender sólo lo específico de REVESTEX con procedencia `AUTHORED`.
2. `CUSTOM_PLATFORM`: conservar la foundation Go/PostgreSQL de esta biblioteca, reutilizar SDKs/proyectos oficiales admitidos y reconocer que las reglas REVESTEX son código nuevo `AUTHORED`, no código de Microsoft/Google/Amazon/Oracle.
3. `BLOCK`: no escribir dominio hasta que aparezca un upstream oficial que satisfaga la exigencia del propietario.

No existe una cuarta opción legítima en la que el agente escriba reglas nuevas y las declare “código de empresa líder”.
