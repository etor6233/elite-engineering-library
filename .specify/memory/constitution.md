# Constitución de mantenimiento de Elite Engineering Library

Versión local: 0.1.0. Estado: requisitos de mantenimiento; no aprobación productiva.
Procedencia: AUTHORED, derivada de las instrucciones del usuario y contratos de la biblioteca.

1. El resultado es una biblioteca portable de conocimiento, código y pruebas para construir sistemas o ampliar sistemas existentes; no una franquicia ya desplegada.
2. Conservar el roadmap REUSABLE_CODE_READINESS_ROADMAP.md §10 como único backlog. No reiniciar arquitectura ni añadir módulos equivalentes sin contrastar sus owners.
3. Cada incorporación preserva fuente oficial, revisión, licencia, notices, cambios y claim demostrado. AUTHORED/ADAPTED nunca se presenta como VERBATIM ni adquiere calidad por fama o compilación.
4. Mantener todas las superficies del contrato de 48 capacidades evaluadas. Su relevancia depende del journey: no imponer todas las tecnologías a todos los proyectos.
5. Un componente aislado no constituye un journey completo. Autorización, efecto durable, respuesta, auditoría, ayuda, soporte, actualización y recuperación deben conectarse y probarse.
6. Registrar fallos y conservar evidencia negativa, corrección canónica, regresión y checkpoint; no reescribir el historial como si el primer intento pasara.
7. No asumir cuentas, credenciales, consentimiento, impuestos, documentos reales, reglas financieras ni gastos. Todo efecto externo material requiere autoridad del target.
8. Reutilizar contexto por referencias y hashes; no releer todo el corpus ni reejecutar gates ajenos al cambio. No omitir gates dependientes para ahorrar tiempo.
9. Los expedientes locales no se distribuyen como aprobaciones de otro proyecto. Mantener los verificadores de contenido y las exclusiones exactas del ZIP.
10. Cerrar sólo por evidencia del alcance declarado. Ni un porcentaje de archivos ni un PASS de estructura prueban producción o un plazo de una semana.

Autoridades de método: AGENT_SYSTEM_START.md, PUBLIC_CODE_ARCHITECTURE_ADMISSION_STANDARD.md,
ENGINEERING_EXECUTION_PLAYBOOK.md y markdown_system/TOTAL_SYSTEM_CAPABILITY_CONTRACT.md.
GitHub Spec Kit aporta la secuencia spec/plan/tasks; esta constitución no es texto publicado por GitHub.
